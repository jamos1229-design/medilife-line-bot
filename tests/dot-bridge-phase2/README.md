# 神メモ第2段階（記憶→dot相談→既存タスクへの反映）テスト

既存の記憶・既存タスク（第1段階のDot連携で関連付け済みの1組）を対象に、dotへの相談用
JSONの作成・コピー、dotからの回答JSONの取込・検証、本人の採用／編集して採用／保留、
採用時のみ既存タスクへ反映する一往復を検証する、合成データのみのテスト群です。
実データ・顧客情報・認証情報は一切含みません。

対象コード：`nexus.html`（`n.html`と同一内容）。第1段階の`schemaVersion:1`・既存画面は
変更せず、`schemaVersion:2`の依頼・応答を別に追加しています。

## 構成

| ファイル | 内容 | 依存 |
|---|---|---|
| `pure.test.js` | 純粋関数の単体テスト（依頼JSONの組み立て・検証、回答JSONの検証＝版不一致・未確認項目の主張・期限の発明・HTML/URL拒否・16KB超過等、コピー内容＝固定の回答指示＋完全な回答例の組み立て、自由文PIIリスク検出、タスクへの反映パッチ計算、中断時の復旧判定、重複依頼防止、保存ヘルパー） | Node.jsのみ |
| `e2e-consult-flow.test.js` | 相談作成〜実際のクリップボードへのコピー〜回答取込〜プレビュー〜採用〜タスク反映の基本往復（省略のない実データで確認）、PRIVATEブロック（コピー直前・取込時・採用直前の3箇所）、不正JSON、版不一致の古い回答拒否、保留からの採用、再取込の重複防止と別内容拒否、採用の反映範囲の限定（タイトル・所要時間・期限のみ、他タスク・他項目は不変）、別タブでの変更の保持、連携OFF/再開、全データバックアップへの包含と復元後の無効化（未適用依頼の再出力要求・採用済み履歴の保持）、保存障害時の非成功表示（復旧用記録・タスク・適用済み記録それぞれの保存失敗、復旧前の競合・削除）、iPhone幅(375/390/430px) | Playwright + ローカルHTTPサーバー |

## 依存関係

- Node.js 18以上
- `pure.test.js`はNode.js標準機能のみで動作し、追加インストール不要です。
- `e2e-consult-flow.test.js`は[Playwright](https://playwright.dev/)を使用し、`tests/dot-bridge/vendor/`配下の
  React本体のローカルコピーをそのまま再利用します（CDNへの依存を避けるため）。本リポジトリの
  `package.json`にはPlaywrightを含めていないため、実行環境に応じて以下のいずれかを用意してください。
  - `npm install -D playwright && npx playwright install chromium`
  - 既にシステム上にPlaywright本体とChromiumがある場合は、`PLAYWRIGHT_CHROMIUM_PATH`環境変数でChromiumの実行ファイルパスを指定できます。

## 実行手順

1. リポジトリのルートで、`nexus.html`を配信するローカルHTTPサーバーを起動します（E2Eテストのみ必要）。
   ```sh
   python3 -m http.server 8793
   ```
   （別のポートを使う場合は、`e2e-consult-flow.test.js`内の`http://localhost:8793/`をあわせて変更してください）

2. 別のターミナルで、リポジトリのルートから各テストを実行します。
   ```sh
   # 純粋関数テスト（Playwright不要）
   node tests/dot-bridge-phase2/pure.test.js

   # E2Eテスト（手順1のサーバーが起動している状態で実行）
   node tests/dot-bridge-phase2/e2e-consult-flow.test.js
   ```
   Playwrightパッケージが`node_modules`から解決できない環境では、`NODE_PATH`にPlaywrightのインストール先を追加してください。

3. 各テストは標準出力に`PASS`/`FAIL`を1件ずつ出力し、最後に合計件数を表示します。`FAIL`が1件でもあれば終了コード1で終わります。

## 残る制約（未確認・未実装の範囲）

- 外部AI（Dot）へのAPI自動送信は行いません。依頼JSONのコピー・応答JSONの貼り付けは、
  いずれも人の操作が必要です。
- Googleカレンダー等への自動登録は行いません。
- 記憶↔タスクの関連付け自体は第1段階の既存画面で行います。未関連の記憶・タスクには
  本機能の入口（🤝 Dotへ相談する）を表示しません。
- 1組の記憶・タスクにつき、同時に進行中（未応答）の依頼は1件のみです。応答前に相談内容
  （質問・未来の意図）を書き直すと、同じ依頼IDのまま内容が更新されます（新しい依頼IDは
  発行されません）。
- facts／unknownsの対象は、第1段階のDot用JSONが持つ5項目（action／status／dueDate／
  durationMinutes／tags）に限定しています。それ以外の項目（感情・希望・金額・売上見込み等）
  は応答JSONに含めても拒否されます（意図的な制限です）。factsは「確認済みフィールド名の配列」
  （unknownsと同じ形式）であり、値そのものは応答JSONに一切含められません（含めても構造上
  受け付けられません）。表示する値は常にNEXUS内部の確認済みデータから取得します。
- 採用時に反映するのはタスクのタイトル・所要時間（dotDurationMinutes）・期限（date）のみです。
  期限は、対象タスクが日付の意味が異なる種類（`kind`が設定されている商談メモの「次にすること」
  等）の場合は更新しません。
- コピー操作では、依頼JSONに加えて固定の回答形式指示とこの依頼用の完全な回答例を一度に
  コピーします（Dot側が形式を誤りにくくするため）。
- バックアップから復元した依頼のうち、まだ採用していないもの（未応答・応答受領済み・保留の
  いずれか）は、復元後は古いものとして扱い、そのままでは採用できません。画面を開いても
  必ず新しく依頼を出し直す必要があります（採用済みの履歴はそのまま保持され、再適用はしません）。
- 最小版は単一タブでの利用を前提としています。Web Locksで単一タブ内の連打・競合は防ぎますが、
  複数タブを同時に開いた場合の完全な安全性までは保証しません（保存直前に必ず最新状態を
  読み直す設計のため、他タブでの変更を上書きすることはありませんが、他タブ側の画面表示が
  自動更新されるわけではなく、古い表示のまま操作しようとした場合は保存時にエラーとして
  検出されます）。
